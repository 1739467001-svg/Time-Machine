## 1. 当前基线

项目已经具备完整主流程：

```text
开场说明 -> 摄像头授权 -> 人脸引导与抓拍 -> 分年龄段生成 -> 时间轴展示 -> 下载/分享
```

当前默认使用 `mock` 引擎，无需 API Key 即可跑通流程；`gemini` 与 `qwen` Provider 已有参考实现，但真实出图质量仍需配置密钥后验证。

已验证：

- `tsc --noEmit` 通过。
- `eslint .` 通过。
- `next build --webpack` 通过。

已发现：

- 默认 `next build` 使用 Turbopack 时，在当前中文路径下会触发内部 panic；短期应使用 webpack 构建，长期可迁移到英文路径或等待/规避 Turbopack 问题。
- README 中提到 `.env.example`，但项目尚未提供该文件。
- 切换云端模型前还缺少阻断式隐私同意流程。

## 2. 完善目标

### 2.1 课程演示目标

- 老师或同学能在本地快速运行并看懂完整流程。
- 无 API Key 时，项目仍可用 `mock` 引擎稳定演示。
- 有 API Key 时，能明确切换到真实云端模型并告知人脸数据流向。
- 答辩时能解释项目架构、隐私策略、模型替换方式和后续优化方向。

### 2.2 产品体验目标

- 用户在上传或生成前清楚知道当前使用的是本地占位引擎还是云端 AI 引擎。
- 云端引擎必须在用户明确同意后才进入拍摄/生成流程。
- 失败时能单段重试，不影响已经生成的年龄段。
- 结果能以长图下载或通过系统分享能力分享。

### 2.3 工程目标

- 保持 `AgingProvider` 插拔式架构，前端不依赖具体模型厂商。
- 保持图像不落盘、不入库、不打日志。
- 默认构建命令应在当前环境稳定通过。
- 环境变量示例、部署说明和开发说明保持一致。

## 4. 第一批实施范围

本轮优先实现 P0，原因是它们直接影响项目能否被安全、稳定、清楚地演示：

2. 在首页展示当前引擎状态。
3. 云端引擎启用时，进入拍摄前显示阻断式隐私同意弹窗。
4. 增加 `.env.example`。
5. 将默认 `build` 脚本切换为 `next build --webpack`，并在 Next 配置中显式声明项目根目录。

## 5. 后续推进建议

### M1：真实模型验证

- 准备 2-3 张不同光线、不同年龄、不同性别的测试照片。
- 分别跑 `gemini` 与 `qwen`。
- 记录每段耗时、失败率、身份保持、年龄递进、成本。
- 根据结果选定默认云端引擎。

### M2：提示词与连贯性

- 为 10/20/30/40/50/60 年分别细化衰老特征。
- 测试“每段都用原图”与“后一段参考上一段输出”的差异。
- 优先保证同一个人，其次保证衰老程度。

### M3：演示交付

- 更新 README：本地运行、云端引擎、隐私说明、构建说明。
- 增加答辩用架构图。
- 准备完整演示脚本：无 Key mock 演示 + 有 Key 真实模型演示。
