# 产品需求文档（PRD）

**项目名称**：时光机 · Time Machine
**文档版本**：v1.0
**日期**：2026-06-17
**性质**：大学课程作业交付物
**受众**：授课教师 / 项目成员

---

> ⚠️ **诚实声明**：时光机是一款**样貌可视化 / 娱乐**产品，**不是科学预测**。AI 生成的是「看起来合理」的衰老样貌，无法真正预知用户未来的长相——它不涉及基因、健康状况、生活习惯等任何真实因素。产品 UI 与所有文档均需明确标注这一点。

---

## 1. 项目概述

「时光机」是一个运行于浏览器的 Web 应用。用户用摄像头拍一张自己的照片，应用调用 AI 对面部进行指令式图像编辑，生成其 **10 / 20 / 30 / 40 / 50 / 60 年后**的样貌，并以一条「人生时间轴」（现在 → +10 年 → … → +60 年）呈现结果。

课程原始需求：「了解自己未来的样子和样貌」。

---

## 2. 目标用户与核心场景

| 维度 | 描述 |
|------|------|
| **主要用户** | 对「未来的自己长什么样」感到好奇的普通用户，包括学生本人及朋友 |
| **使用设备** | 带摄像头的 PC / 笔记本（主要），未来可扩展至手机浏览器 |
| **典型场景** | 独自或与同学围观：启动网站 → 允许摄像头 → 拍照 → 等待 AI 生成 → 逐帧惊叹时间轴 |
| **评分优先级** | 老师最看重**最终视觉效果**（变老结果像不像、惊不惊艳），其次是工程完整度 |

## 3. 功能需求

优先级说明：**P0** = 必须完成 / **P1** = 应完成 / **P2** = 有余力再做。

### 3.1 用户流程

```
开场引导  →  摄像头授权  →  实时预览+人脸引导框
  →  检测到人脸  →  用户点击抓拍
  →  后端按 10 年步长连续生成 6 个年龄段  →  前端逐张呈现时间轴
  →  用户浏览 / 导出 / 重新拍
```

|---|------|--------|------|

## 4. 变老引擎技术选型

> 这是项目最大的技术风险点：图像生成质量直接决定课程评分。

### 4.1 方案对比

| 方案 | 技术路线 | 图像质量 | 身份保持 | 成本 | 隐私 | 适合场景 |
|------|----------|----------|----------|------|------|----------|
| **nano-banana（Gemini 2.5 Flash Image）** ⭐ 主引擎 | 指令式扩散模型图像编辑 | ★★★★★（2026 SOTA） | 极强 | ~$0.039/张，6 段≈$0.23/人（约¥1.7） | 人脸上传 Google，需告知 | 追求最佳视觉效果 |
| FLUX.1 Kontext | 指令式扩散模型 | ★★★★ | 强 | 按次计费 / dev 版可自托管 | 可自托管 | 构图/身份稳定 |
| Qwen-Image-Edit | 开源扩散模型 | ★★★★ | 较强 | 开源免费，需 GPU | 可完全本地 | 隐私优先 / 预算有限 |
| 字节 Seedream/SeedEdit | 专有模型 | ★★★★ | 强 | API 按次计费 | 人脸上传第三方 | 真实感强 |
| **SAM（yuval-alaluf/SAM）** ⭐ 兜底 | StyleGAN 专用变老 GAN | ★★★（2021 技术） | 较好 | 开源；Replicate 按次或自托管 | 可自托管 | 精确指定岁数 / 免费离线 / 隐私 |
| 消费级 API（YouCam、PixelBin 等） | SaaS 黑盒 | ★★★ | 一般 | 有免费额度 | 外传数据，可能带水印 | 快速验证 |

**学术参考**：论文「TimeMachine: Fine-Grained Facial Age Editing with Identity Preservation」（arXiv 2508.11284, 2025）与本项目同名，研究方向正是「精确年龄编辑 + 身份保持」，列入参考文献。

**开源参考实现**：`steven-tey/extrapolate`（GitHub），技术栈 Next.js + Vercel + Replicate + Cloudflare R2，是一个功能相近的 Web 版人脸变老应用，架构可参考。

### 4.2 选型决策

- **主引擎**：nano-banana（Gemini 2.5 Flash Image）—— 视觉效果当前最优、成本极低、接入简单。
- **兜底引擎**：SAM —— 在需要精确年龄控制、无 API Key、或有隐私顾虑时使用。
- **架构原则**：变老能力抽象为可插拔 `AgingProvider` 接口，不被单一模型/厂商绑死；新增引擎只需实现接口并在工厂函数加 `case`，前端与 API 层零改动。

## 5. 技术架构

技术栈：**Next.js 16（App Router）+ React 19 + TypeScript + Tailwind CSS v4**

### 5.1 核心数据流

```
浏览器（摄像头抓拍或导入照片 → base64 图）
   │
   ├─► POST /api/age { 原图, y10, source=0 } ─► +10 结果
   ├─► POST /api/age { +10, y20, source=10 } ─► +20 结果
   ├─► …
   └─► POST /api/age { +50, y60, source=50 } ─► +60 结果
                  │
                  └─► getAgingProvider() ─► mock | gemini | qwen

   AgeTimeline / ResultCard × 7  ◄───── 各段 AgedImage（逐张返回）
```

> 说明：单年龄段接口按 10 年步长连续调用，每张图就绪即展示；失败时从最近
> 成功阶段继续推演，避免重新支付已经完成的模型请求。

### 5.2 目录结构

```
src/
  app/
    page.tsx              # 主流程：开场 → 抓拍 → 时间轴（逐张回填 / 导出 / 分享）
    api/age/route.ts      # 后端：生成单个年龄段，图像仅内存处理
  components/
    CameraCapture.tsx     # 摄像头 + 人脸引导框 + 抓拍
    AgeTimeline.tsx       # 现在 → +10…+60 时间轴
    ResultCard.tsx        # 单个年龄段卡片（加载 / 完成 / 失败重试）
  lib/
    ages.ts               # 年龄段配置（id / yearsFromNow / label）
    aging-filter.ts       # 占位变老的 CSS/Canvas 滤镜（卡片与长图共用）
    face/
      use-face-detector.ts  # MediaPipe 人脸检测 hook（带降级）
    share/
      compose-timeline.ts   # 合成可下载/分享的时间轴长图
    aging/
      types.ts            # AgingProvider 接口 / AgingRequest / AgedImage
      index.ts            # 工厂函数：按 AGING_PROVIDER 选引擎
      mock-provider.ts    # 本地占位，CSS 滤镜模拟（无需 API Key）
      gemini-provider.ts  # nano-banana 参考实现
      prompt.ts           # 变老提示词构建
```

### 5.3 引擎切换方式

```
# .env.local
AGING_PROVIDER=gemini        # 或 mock（默认）
GEMINI_API_KEY=<your_key>
```

| 维度 | 要求 |
|------|------|
| **性能** | 6 个年龄段连续生成；单张目标尺寸约 512 px；前端逐张呈现，保证年龄轨迹连贯 |

| **可维护性** | Provider 可插拔、TypeScript 类型完备、构建与类型检查通过 |
| **可扩展性** | 新增引擎只需实现 `AgingProvider` 接口，前端零改动 |

## 7. 隐私与伦理

人脸属于《个人信息保护法》定义的**敏感生物特征数据**，本项目将其作为一等公民处理。

**已实现的默认行为**

- 图像**仅在内存中处理**，请求结束即丢弃，不落盘、不入库、不打日志。
- 默认 `mock` 引擎完全在本地运行，数据不出设备。

**切换云端引擎时的要求**

- 切换到 Gemini 等云端引擎前，UI 必须明确告知用户「你的人脸照片将上传至 Google 服务」，并获得明确知情同意后方可继续。
- 不得在未经同意的情况下静默上传人脸数据。

**用途声明**

- 本产品仅供本人娱乐使用，不得用于：伪造他人容貌、身份验证、歧视性判定、或任何商业用途。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 变老出图质量不达预期 | 直接影响课程评分（最高风险） | M1 先做 spike 验证；Provider 可切换，实在不行兜底 SAM |
| 隐私与数据外传 | 合规 / 用户信任 | 默认本地 mock；云端引擎需明确同意；不持久化 |
| 第三方 API 价格/可用性变化 | 成本或可用性 | 抽象 Provider 接口；保留开源自托管路线（SAM / Qwen） |
| 网络/算力限制 | 云端出网受限，或自托管需要 GPU | 文档中说明要求；优先云端 API，备选开源模型 |
| 浏览器摄像头兼容性 | 用户无法拍照 | 要求 HTTPS / localhost；FaceDetector 不支持时自动降级 |

## 10. 验收标准

以下标准可在演示时逐项检验：

1. **完整流程可跑通**：在受支持的浏览器中，能完成「摄像头授权 → 人脸引导 → 抓拍 → 后端生成 → 时间轴展示」全流程，无崩溃或白屏。
2. **6 个年龄段都有结果**：时间轴上「现在」+「+10 至 +60 年」共 7 张图均正常渲染。
3. **视觉效果（核心标准）**：接入真实引擎（gemini）后，6 段结果「能看出明显的年龄递进趋势，且仍能辨认出是同一个人」。
4. **隐私声明可见**：切换至云端引擎前，UI 明确展示数据流向说明并要求用户确认。
5. **构建与类型检查通过**：`pnpm build` 与 `tsc --noEmit` 无报错。
6. **引擎切换可验证**：仅改动 `.env.local` 中 `AGING_PROVIDER` 的值，即可在 mock 与 gemini 引擎之间切换，前端无需改动。
